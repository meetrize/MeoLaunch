# 14 — meoLaunch 半年增长与变现计划

> 主线：前三个月开源可信 + 中文内容起量；后三个月英文出海 + Pro 变现 + 渠道铺垫。  
> 制定背景：用 Launchpad 替代扩大知名度与影响力，吸引流量，并最终直接或间接盈利。  
> 起算：以对外可安装版本就绪为 Month 1 起点（可按实际发布日平移）。

## 总目标（第 6 个月末）

- 有可对外传播的稳定产品 + 官网 + 自动更新
- 中文圈形成可感知口碑（下载 / Star / 内容曝光）
- 英文完成至少一次正式发布，开始有付费收入
- 个人品牌「极致轻量 macOS 工具」立住，为下一款产品铺路

## 主 KPI

| 指标 | 3 月末 | 6 月末 |
|------|--------|--------|
| GitHub Stars | 500+ | 1,500+ |
| 累计下载 / 活跃安装（估） | 2,000+ | 8,000–15,000 |
| 内容曝光（文章+视频累计阅读/播放） | 5 万+ | 20 万+ |
| 邮件 / 社群名单 | 200+ | 800+ |
| 付费收入 | ¥0（蓄水） | 有第一笔；月入目标先定 $500–2,000 |

## 策略摘要

| 阶段 | 月份 | 重心 | 对应路线 |
|------|------|------|----------|
| 地基 | M1 | 可发布、可信任 | 分发与叙事资产 |
| 起量 | M2 | 半开源 + 中文首波 | 开源获信任 + 内容驱动 |
| 蓄水 | M3 | 口碑巩固 + Pro 定稿 | 仍不正式收费 |
| 出海 | M4 | Product Hunt / Show HN + 软收费 | 英文社区 |
| 放大 | M5 | 转化优化 + 渠道申请 | Setapp / 正版货架 |
| 收束 | M6 | 稳定变现 + 矩阵预告 | 个人品牌 / 产品矩阵 |

单人精力建议：**产品 50% / 内容与触达 40% / 杂务 10%**。

---

## 第 1 月：可发布、可信任（地基）

**主题：** 产品达到「敢让陌生人装」的标准；叙事与资产准备好。

### 产品

- [ ] Developer ID 签名 + Apple 公证（Notarization）
- [ ] Sparkle（或同类）自动更新跑通
- [ ] 卸载干净、权限引导清晰（辅助功能一步步说明）
- [ ] 固定对外版本号（如 1.0.0），CHANGELOG 中英双语
- [ ] 做出**核心传播资产**：Activity Monitor 内存对比图 + 15–30 秒唤起对比视频

### 分发

- [ ] 官网 MVP：下载、功能 3 点、内存数字、Privacy、更新日志（中英可先中文为主、英文摘要）
- [ ] DMG/ZIP 安装体验打磨（首次打开不报毒、说明写清）
- [ ] GitHub 仓库整理：README 中英、截图、GIF、对比表、Star 引导
- [ ] 准备 Homebrew Cask 提交材料（本月提交或下月合并均可）

### 增长准备

- [ ] 下载页加邮件订阅（或微信群 / 即刻圈子二选一，国内优先社群）
- [ ] 列出 20 个待触达账号：少数派作者、B 站 Mac 区、V2EX 常客、小红书数码博主

### 月末验收

- 陌生人按官网 3 步能装上并用热角唤起
- 有一张「一眼懂」的对比图
- README 打开不丢人

---

## 第 2 月：半开源亮相 + 中文首波（起量）

**主题：** 用「真·原生轻量」换信任；完成第一次中文爆发尝试。

### 产品 / 开源策略

- [ ] 确定开源边界（建议：核心扫描 / 网格 / 热角开源；部分 Pro 预留不开——或先全开源观察 1 个版本）
- [ ] LICENSE、贡献指南、Issue 模板（bug / feature）
- [ ] Homebrew 安装可用（Cask 名称以实际为准）

### 内容（本月主战场）

- [ ] 深度长文 1 篇：《为什么我重写了 Launchpad（内存/唤起数据）》——投少数派投稿 / 自发后求转载
- [ ] V2EX 分享帖 1 篇（真诚技术向，少硬广）
- [ ] B 站 / 短视频 2–3 条：内存对比、热角演示、搜索秒开
- [ ] 小红书 3–5 条图文（痛点：Launchpad 卡、索引乱、想极简）

### 触达

- [ ] 私信 / 邮件 10 个中腰部博主送体验包（附 15 秒素材 + 一句话卖点）
- [ ] 收集用户反馈，每周修 3 个最高频体验问题

### 月末验收

- 至少 1 篇被有效传播的中文内容（转载 / 评论区活跃即可）
- Star 与下载开始有自然曲线
- 邮件 / 社群名单启动

---

## 第 3 月：口碑巩固 + Pro 功能定稿（蓄水结束）

**主题：** 把「用过的人愿意转发」做扎实；锁定收费边界，**本月仍不正式收费**。

### 产品

- [ ] 根据反馈打磨：稳定性、多屏、搜索、文件夹 / 排序（优先最影响口碑的项）
- [ ] 明确 Free vs Pro 切分（可微调）：

| Free | Pro（买断建议 $9–19 / ¥68–128） |
|------|----------------------------------|
| 基础网格、搜索、热角、低内存 | 高级布局 / 主题、多触发方式、多屏策略、布局备份同步、优先支持… |

- [ ] 埋点克制：至少能统计版本更新成功、大致活跃（注意隐私文案）
- [ ] 英文官网完整版草稿完成（下月要用）

### 内容

- [ ] 复盘第 2 月数据，复制有效形式再发 2 条内容
- [ ] 「更新日志式」短内容：每月版本亮点，培养「作者还在认真做」的印象
- [ ] 开始 build in public：每周 1 条进度（即刻 / X / 博客三选一坚持）

### 月末验收（对应 3 月末 KPI）

- Star ≥ 500 或下载累计 ≥ 2,000（差一截就延长内容，别急着出海收费）
- Free / Pro 边界写进文档，工程上能开关
- 英文素材（截图、文案、对比）齐备

---

## 第 4 月：英文发布 + 软收费（出海第一枪）

**主题：** Product Hunt / Show HN；开启付费，预期保守。

### 发布

- [ ] Product Hunt 上线（周二–周四；Maker 评论、图集、GIF、首评话术提前写好）
- [ ] Show HN + r/MacApps / r/macapps 同步
- [ ] 英文一句话定位：`Launchpad replacement. Native. Tiny memory. Instant.`（避免和 Raycast 比全能）

### 变现

- [ ] 接入支付：Lemon Squeezy / Paddle（含税发票对海外友好）
- [ ] Pro 许可证校验 + 优雅降级（未购仍可用 Free）
- [ ] 定价先简单：Free + 一次买断；早期不上复杂订阅（除非进 Setapp）
- [ ] 早鸟价 2–4 周（如 $9 → 后 $15），制造窗口感

### 内容

- [ ] 英文短文 / 推文线程：memory footprint story
- [ ] 回复每一个 PH / Reddit 认真评论（转化关键期）

### 月末验收

- PH 有曝光（名次其次，评论质量更重要）
- 出现第一笔付费（哪怕很少）
- 支付与授权链路无重大事故

---

## 第 5 月：转化优化 + 渠道申请（放大收入）

**主题：** 把「看过的人」变成「装上的人」和「付钱的人」；铺被动分发。

### 产品 / 转化

- [ ] 官网加：对比表、FAQ、短演示、Pricing 页
- [ ] 首次运行「价值时刻」：打开即看到搜索 / 热角引导，3 秒内感到快
- [ ] 根据流失点修：公证弹窗说明、辅助功能引导、更新失败
- [ ] 中文区可同步开售（卡支付官网为主；微信 / 支付宝视接入成本决定）

### 渠道

- [ ] 提交 Setapp 或同类（周期长，本月提交即可）
- [ ] 评估 Mac App Store：作橱窗可，完整能力可留官网（双轨常见）
- [ ] 接触 1 个 Bundle / 正版渠道（如数码荔枝）谈合作档期

### 内容

- [ ] 用户证言页（截评论授权）
- [ ] 再找 5 个英文或中文评测（用 Pro 兑换码）
- [ ] 一篇「独立开发半年复盘」（利于个人品牌）

### 月末验收

- 付费转化路径可复盘（访问 → 下载 → 试用 → 付费）
- Setapp / 渠道申请已递出
- 月收入有可观察趋势，而不是偶发一单

---

## 第 6 月：稳定变现 + 矩阵预告（收束与下一跳）

**主题：** 把半年成果固化成「可预期的小生意」；预告下一款，完成品牌闭环。

### 经营

- [ ] 定下标准定价（早鸟结束）与退款政策
- [ ] 支持流程：邮箱模板、常见问题、更新节奏（如每 3–4 周一小版）
- [ ] 复盘 KPI：哪条渠道 ROI 最高，下半年加倍；无效渠道砍掉

### 增长

- [ ] 若 Setapp 未过：继续优化差异化卖点与稳定性后复申
- [ ] 做一次「版本里程碑」传播（1.x 正式版 / 半年纪念）
- [ ] 维护者形象：公开路线图（哪些永远免费、哪些 Pro）

### 矩阵预告

- [ ] 从现有用户问卷：下一个最想要的轻量工具（剪贴板 / 窗口 / 菜单栏监控等）
- [ ] 选出**一个**下一款方向，写一页设想，向邮件列表预告（可不开发，先占心智）

### 月末验收（对应 6 月末 KPI）

- 月收入进入「有基础、可优化」状态（先冲 $500–2,000/月）
- 名单 ≥ 800，可直接触达下一款
- 能说清：meoLaunch 靠什么渠道活、下一步加什么

---

## 每周固定节奏

| 日 | 做什么 |
|----|--------|
| 周一 | 产品：修反馈 Top3 / 发小版本 |
| 周三 | 内容：1 条短内容或回复社区 |
| 周五 | 增长：触达 2 个博主或发 1 帖 |
| 周日 | 30 分钟看数据：下载、Star、邮件、收入 |

---

## 明确不要做的事（防分心）

- 前 3 个月不上插件市场、不搞复杂订阅、不和大启动器正面开战
- 不并行「重做 UI 大改版 + 出海 + 进所有渠道」
- 不为了开源而开源到无法收费——**第 3 月前必须定死 Free / Pro**
- 不把时间花在完美官网动画上，优先公证、更新、对比视频

---

## 检查点（去 / 留决策）

### 第 3 月末

- 若几乎无下载、无讨论：先别收费，回头补内容与稳定性 4–6 周
- 若有稳定口碑：按计划第 4 月出海收费

### 第 6 月末

- 收入与名单都弱：收缩到维护模式 + 一条最有效内容渠道
- 收入或名单任一达标：加码该渠道，并启动第二款产品预研

---

## 差异化话术（对外统一）

- 中文：原生 AppKit（非 Electron）、常驻内存极低、热角 / 搜索即开的 Launchpad 替代
- 英文：`Launchpad replacement. Native. Tiny memory. Instant.`
- 避免：与 Raycast / Alfred 比「全能启动器」；主打 Launchpad 体验与资源占用
